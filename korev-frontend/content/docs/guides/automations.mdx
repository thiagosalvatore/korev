---
title: Automations
description: 'Run a prompt on a timer and let it open workspaces.'
---

An automation runs a prompt every few minutes while Korev is open. It can open a workspace for each piece of work it finds. For example, it can check your support tickets every 10 minutes and open a workspace for each new one that needs a code change.

## Create one

1. Click **Automations** in the sidebar, then **New automation**.
2. Give it a name and write the prompt. Say what to look at and when a workspace is worth opening, for example: "Read my open support tickets. For each one assigned to me that is not in progress and needs a code change, open a workspace to fix it."
3. Set how often it runs, in minutes.
4. Pick the repositories it can open workspaces in. Leave this empty for an automation that only reports.
5. Click **Create automation**.

The first run starts within a minute. Click **Run now** to start one at once, and use the switch to pause the automation.

## What a run does

Each run is a new chat with your default agent, in a scratch folder that is not a repository. The agent uses the same tools, MCP servers and `gh` sign-in as your other chats, so it can read tickets from wherever your tools reach.

Nobody watches a run, so its tool calls run without approval, as they do in a workspace when **Tool approvals** is off.

At the end of its reply, the agent lists the workspaces to open. Each one has a repository, a key and a prompt. The key names what the workspace handles, such as a ticket id. Korev then opens each workspace and sends the prompt to a new agent there, with the same defaults as a workspace you create.

Korev checks each request first:

- **The repository must be one of the automation's.** Requests for other repositories are skipped.
- **One workspace per key.** Korev remembers every key the automation used and skips repeats, so a ticket gets one workspace, not one every 10 minutes. The agent also sees the keys already used.
- **At most five workspaces per run.**
- **One run at a time.** A run does not start while the last one is still going.

When a run opens workspaces, Korev sends a notification.

## Check on runs

The Automations page lists the last five runs of each automation:

- when the run started,
- what it did, such as **Opened 2 workspaces** or **Nothing to open**,
- the workspaces it opened,
- a note for each request Korev skipped.

Click a run's time to open its chat and read the whole reply. You can send it a follow-up message there. Korev keeps the last 20 runs of each automation. Runs do not show in the sidebar's Ask chats.

## Limits

- Automations run only while Korev is open. Closing the window is fine, but quitting stops them. When Korev starts again, an automation that is due runs once. It does not catch up on missed runs.
- The interval is in minutes. There is no schedule for a time of day yet.
