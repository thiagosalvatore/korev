## See what changed

The right panel has four tabs: **Files**, **Changes**, the pull request tab and **Artifacts**. The pull request tab shows the pull request's number, such as **#42**, or **PR** before there is one.

**Changes** lists every file that differs from the workspace's target branch. From there:

- **Diff** opens the diff view (⌘⇧D).
- **Review** opens a new chat that reviews the changes. See [Review model](../concepts/agents-and-modes.mdx#review-model).
- **Explain** opens a walkthrough of the changes in plain words. See [Explain a pull request](./explain-a-pull-request.mdx).

**Files** lists the files of the worktree. Click one to read it, with syntax highlighting for most languages. Files over 200,000 characters show as plain text. ⌘A in the file selects only its text. When a file that a chat links to is missing, the tab says so. When Korev cannot show a file, such as a video or a file over 1 MB, **Open outside Korev** lets you reveal it in Finder or open it in its default app.

To review a teammate's pull request, open **Pull requests** in the sidebar. See [Pull request inbox](./pull-request-inbox.mdx).

After each agent turn, the chat shows "N files changed". Click it to see only that turn's changes.

## Comment for the agent

In the diff view, switch between **Unified** and **Split**. Click **Comment on this line** next to a line to leave a comment. When you have comments, press **N comments ready to send** to put them in the composer, then send them to the agent.

Tick **Viewed** on a file to collapse it. It opens again if the file changes.

Press **Edit file** to change a file yourself. ⌘S saves.

## The next git action

The button in the workspace header always shows the next step:

| Button                                    | What it does                                                                                                                                                                                                                                                                                                                                                           |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Create PR** (⌘⇧P)                       | Asks the agent to commit, push and open a pull request against the target branch with `gh pr create`                                                                                                                                                                                                                                                                   |
| **Resolve conflicts**                     | Asks the agent to fix the pull request's merge conflicts                                                                                                                                                                                                                                                                                                               |
| **Fix errors** (⌘⇧X)                      | Sends the failing checks and their links to the agent                                                                                                                                                                                                                                                                                                                  |
| **Merge** (⌘⇧M)                           | Runs `gh pr merge --squash`                                                                                                                                                                                                                                                                                                                                            |
| **Merge partial stack** / **Merge stack** | Shown for a pull request in a GitHub stack that has open pull requests below it. Runs `gh stack merge <number> --yes --squash`, which merges that pull request and every open one below it in one step. If any open pull request below isn't ready (conflicts, failing or running checks, draft, or review needed), the button shows **Stack can't be merged** instead |
| **Archive**                               | Archives the workspace once the pull request merges                                                                                                                                                                                                                                                                                                                    |

**Create PR**, **Resolve conflicts** and **Fix errors** send a prompt to the active chat with plan mode off. Add your own instructions to these prompts with [`[prompts]`](./configure-your-repository.mdx#prompts).

While checks run, or while the pull request waits for review, the button shows that state instead.

Only the checks that the repository requires for merge count. If a check that is not required is still running or has failed, the button shows **Merge**. If the repository requires no checks, the button shows **Merge** while checks run. If Korev cannot find out which checks are required, it counts all of them.

## Checks

The pull request tab shows the pull request:

- Its state, conflicts, failing and running checks, and review status.
- The list of checks. Click one to open it on GitHub.

Korev refreshes the pull request after each agent turn, every 30 seconds while the workspace's agent is working, and every 2 minutes otherwise. Change this in **Settings → Git → Check pull requests**. Once a pull request is merged or closed, Korev stops asking GitHub about it. When GitHub limits your requests, Korev waits until the limit resets.

## Comments

Under the checks, the pull request tab shows the comments on the open pull request as threads. A thread on a line shows the code it is about and every reply. Comments on the pull request itself and review summaries show as **Conversation**.

- **Humans** and **Bots** split the threads by who started them. Bots are GitHub apps, such as CodeRabbit or Codecov.
- A resolved thread starts closed. Click it to open it.
- **Add to chat** puts the whole thread in the composer for the agent.
- **Diff** opens the file in the diff view, where the thread also shows under its line.
- **Open as tab** opens the same view as a tab next to your chats, with more room to read.

## Keep PRs ready

Turn on **Settings → Git → Keep PRs ready**, and Korev sends a workspace's open pull request to the workspace's agent when it needs work. That is when it has merge conflicts, a failing required check, or a review comment that waits for your answer. The agent fixes the problem, commits and pushes.

- Korev sends each problem once. If the agent cannot fix it, the workspace shows under [Waiting for you](../concepts/workspaces.mdx#waiting-for-you) and Korev does not try again. A new failure after a push, or a new reply from a reviewer, is a new problem.
- Korev never interrupts the agent. If a chat in the workspace is running, Korev waits until its turn ends.
- **Answering reviewers** sets what the agent does on GitHub after it handles a review comment: **Reply on each thread** (the default), **Reply and resolve**, **Don't post anything**, or **Custom**, which follows your own instruction. The agent posts as you.
- To turn it off for one workspace, untick **Keep PR ready** in the workspace's **…** menu in the sidebar, or press **Keep PR ready** in the workspace header.
- To keep one pull request ready, also with the setting off, click **Keep ready** on its row on the **Pull requests** page. If no workspace has the pull request, Korev checks it out in a new workspace first. Click **Keep ready** again to stop.

The prompt uses your [`[prompts]`](./configure-your-repository.mdx#prompts) instructions for `resolve_merge_conflicts` and `fix_errors`. Add instructions for the review comments with `address_review`.

## Archive on merge

Turn on **Settings → Git → Archive on merge**, or set `[git] archive_on_merge = true`, and Korev archives each workspace when its pull request merges.

To keep one workspace open after its merge, for example to finish work by hand, turn on **Keep after merge**. It is in the workspace's **…** menu in the sidebar and on the New workspace page.
